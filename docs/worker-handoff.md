## Build

### Submodules

From the repository root:

```bash
git submodule update --init --recursive
```

The project uses Premake and the dependencies listed in `.gitmodules`. Missing
submodules produce misleading compiler errors later, so initialize them first.

### Native Windows build

The supported native workflow is:

```bat
generate.bat
```

Open the generated `build/boiii.sln` in Visual Studio 2022, select `Release` and
`x64`, and build. The CI equivalent is:

```text
msbuild /m /v:minimal /p:Configuration=Release /p:Platform=x64 /p:PlatformToolset=ClangCL build/boiii.sln
```

Required native tools are Visual Studio 2022, the Windows 10/11 SDK, ClangCL,
Git, and the project submodules. Output is written to
`build/bin/x64/Release/`.

### Unix cross-build

`scripts/unix/cross.sh` targets `x86_64-windows-msvc` with LLVM and an MSVC
sysroot. It requires `clang`, `clang++`, `clang-format`, `stylua`, `gmake`,
`premake5`, and the LLVM binutils. The sysroot must contain `bin`, `lib`, and
`include` directories in this layout:

```text
WINDOWS_MSVC_SYSROOT/
  bin/x86_64-unknown-windows-msvc/
  lib/x86_64-unknown-windows-msvc/
  include/
```

## Runtime Makeup

### ext.dll loading

`extension.cpp` loads `game::get_appdata_path() / "ext.dll"` and invokes these
exports:

| boiii lifecycle | Export | Meaning |
| --- | --- | --- |
| constructor | DLL load | Load the extension library |
| `post_load()` | `_1` | Validate the host and construct components |
| `post_unpack()` | `_2` | Install selected hooks and patches |
| `pre_destroy()` | `_3` | Unpatch or shut down components |

Do not remove this loader until native replacements have been runtime-tested.

### boiii hook model

Most game addresses are declared as `WEAK symbol<...>` values and selected with
`game::select(client_address, dedicated_address)`. Client addresses normally
use image base `0x140000000`; dedicated addresses are separate and resolved
relocatable using `_g` runtime selection. The dedicated server binary
`BlackOps3_UnrankedDedicatedServer.exe` is available in `/home/tim/t7_full_game/`.

The custom connectionless path builds packets as:

```text
FF FF FF FF + command + separator + payload
```

For a negotiated password peer, `network.cpp` inserts the two password marker
bytes after the separator and appends a little-endian 16-bit password-mixed
checksum. Discovery `getInfo` and the initial `infoResponse` remain unprotected
until the server advertises `net_password_required=1` and
`net_password_scheme=1`.

### Ghidra address rules

- `0x180...` addresses in `/ext.dll` and `/t7patch.dll` are addresses inside
  those DLLs.
- `base+0x...` in t7patch decompilation refers to the loaded host game's image,
  not the t7patch DLL itself.
- In the current client dump, `base+0x1ef6a30` is `0x141ef6a30`.
- Always pass the explicit `program` argument when multiple programs are open.
- Static runtime-populated function-pointer tables may read as zero. Follow
  writes in installers such as `protection_install` instead of treating a zero
  table entry as an absent function.

### Recommended analysis workflow

1. Confirm the open programs and image bases with `ghidra_list_open_programs`.
2. Locate a function with `ghidra_get_function_by_address` or string/xref
   searches.
3. Read both `ghidra_decompile_function` and
   `ghidra_disassemble_function`; decompiler output alone can misidentify
   thunks, import wrappers, and branch continuations.
4. Use `ghidra_get_xrefs_to` on named functions and data tables, then inspect
   the installer or caller context with `ghidra_get_assembly_context`.
5. For runtime-populated targets, inspect the writes in the patch installer and
   map the host-relative offset to `src/client/game/symbols/`.
6. Rename only after the call signature and behavior are confirmed. Add a
   plate comment with source anchors and uncertainty when needed.
7. Save the Ghidra program after a transaction is complete. If a save fails,
   check for an active transaction before making more edits.

Useful MCP-style queries include:

```text
decompile /t7patch.dll at 0x180041FC0
decompile /t7patch.dll at 0x180009A60
decompile /games/BlackOps3.dump.post_unpack.exe at 0x142177980
get xrefs to 0x18008FBC0 in /t7patch.dll
read memory at 0x1800B0300 in /t7patch.dll
```

The exact callable tools are `ghidra_decompile_function`,
`ghidra_disassemble_function`, `ghidra_get_xrefs_to`,
`ghidra_get_assembly_context`, `ghidra_read_memory`,
`ghidra_rename_function_by_address`, `ghidra_set_plate_comment`, and
`ghidra_save_program`.

## t7patch.dll Makeup

The main t7patch entry is `run_patching` at `0x1800153A4`. It calls or reaches
the following major installers:

- `protection_install` at `0x18003ECA0`: host symbol resolution, protection
  hooks, Steam-interface patches, and CFG-related setup.
- `game_dvar_and_hook_installer` at `0x180041800`: dvar/security state setup,
  including initialization of the network password hash.
- `lobbyvm_install_joinablecheck_patch` at `0x180009A60`: LobbyVM Lua patch.
- `infra_cfg_dispatch_hook_install` at `0x1800162C4`: CFG dispatch support.
- `infra_thread_freeze_thaw_unload` at `0x18001F500`: thread freeze/thaw around
  patching and unload operations.

### Network password targets

These are annotated in `/t7patch.dll`:

| Function | Address | Behavior |
| --- | --- | --- |
| `network_password_validate_marker` | `0x180014EC0` | Checks marker bytes from hash bits 16 and 24 |
| `network_password_write_marker` | `0x180014FD0` | Writes those marker bytes after the native serializer |
| `network_password_mix_checksum` | `0x180015C00` | XORs the checksum with the hash low 16 bits |
| `network_password_validate_checksum` | `0x180015C64` | Validates current/previous checksum and strips two bytes |
| `network_password_set_hash` | `0x180030FE0` | Rotates current/previous hash and records time |
| `SetNetworkPassword` | `0x180041FC0` | Lowercase FNV-1a-64 hash and state update |
| hash routine | `0x18001F960` | Lowercase FNV-1a-64, high bit cleared |

The previous hash is accepted for 1500 ms after a change. The current boiii
implementation matches these primitives at its custom connectionless boundary,
but does not claim to hook the native game serializer/parser targets.

### LobbyVM target

The embedded chunk replaces `LobbyVM.JoinableCheck`, preserves local requests,
limits available slots using `party_maxplayers`, rejects closed and
friends-only parties, and replaces `LobbyVM.OnDisconnect` with a no-op. The
current boiii replacement is in `ui_scripting.cpp` and runs after
`UI_CoD_LobbyUI_Init` on `s_lobbyLuaVM` using protected HKS execution.

### Other t7patch-only behavior

- `lobby_validate_join_request` and `friends_cache_contains_xuid`: native
  friends-only admission path, not yet fully reproduced in boiii's native game
  lobby path.
- `ANTICHEAT_TEST_FUNCTION` and `ANTICHEAT_TEST_FUNCTION2`: self-tests using
  sentinel `0x8f7fecc4` and an `int 0x29` fast-fail path.
- `infra_cfg_dispatch_hook_install`: writes `_guard_check_icall` into a CFG
  dispatch slot after matching known prologues.
- `protection_install`: Steam ownership/DLC caching and additional host hooks.
